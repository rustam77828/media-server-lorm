# Конституция проекта

## Media Server LORM

**Версия:** 1.0
**Дата:** 2026-09-13

---

## 1. Назначение

Система предназначена для наблюдения за состоянием локального медиа-сервера (Nextcloud), объяснения происходящих процессов и помощи администратору в принятии решений по управлению сервером.

## 2. Область применения

- **Сервер:** `mediaserver` (Ubuntu 26.04 LTS)
- **Сеть:** локальная, статический IP (диапазон 192.168.x.x)
- **Доступ:** только по SSH-ключам с доверенного устройства
- **Питание:** BIOS настроен на автозапуск после возврата электричества
- **Приложение:** Nextcloud в Docker (`nextcloud-app`, `nextcloud-db`)

## 3. Принципы

### 3.1. Безопасность прежде всего

- Доступ только по SSH-ключам.
- Пароли отключены.
- Все действия логируются.
- Никаких автоматических удалений данных без подтверждения.

### 3.2. Отказоустойчивость

- Статический IP — сервер всегда доступен по одному адресу.
- Автозапуск после сбоя питания (BIOS).
- Мониторинг состояния — при отклонениях система сообщает.

### 3.3. Постепенность доверия (LORM)

- **L0:** знать, что есть на сервере.
- **L1:** наблюдать за состоянием.
- **L2:** объяснять, почему так происходит.
- **L3:** предлагать действия.
- **L4:** выполнять с одобрения человека.
- **L5:** автономные действия — только по письменной политике.

### 3.4. Прозрачность

- Каждое действие можно объяснить.
- Каждое действие можно отменить (rollback), если это возможно.
- Каждое действие оставляет след в логах.

### 3.5. Ограничения

- Система не удаляет данные без подтверждения.
- Система не выполняет действия, результат которых нельзя проверить.
- Система не работает с внешней сетью без явного разрешения.
- Система не хранит пароли в открытом виде.

## 4. Технологии

- **ОС:** Linux (Ubuntu 26.04 LTS)
- **Приложение:** Nextcloud (Docker)
- **Доступ:** SSH-ключи (ED25519)
- **Мониторинг:** системные метрики, Docker API
- **Backend:** Python 3.x, FastAPI
- **Frontend:** HTML, CSS, JavaScript
- **Логи:** journalctl, auth.log, Docker logs
